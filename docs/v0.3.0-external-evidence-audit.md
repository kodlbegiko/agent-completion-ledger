## Security finding discovered during operations preparation

The benign mixed-case URL case revealed that v0.3.0 checks command arguments using a case-sensitive `http://` / `https://` prefix test. An argument beginning with `HTTPS://` was passed to the allow-listed interpreter rather than rejected by ACL.

This does not make ACL a sandbox bypass—ACL is explicitly not a sandbox—but it contradicts the documented remote-URL rejection boundary. The merged correction normalizes each argument before the prefix comparison and adds parameterized lower- and uppercase regression tests plus an end-to-end reproduction case.

Until a patch release is verified:

- use `--no-exec` for external untrusted repositories;
- do not describe v0.3.0 executable-mode URL rejection as complete;
- do not request external maintainers to rely on v0.3.0 as an execution isolation boundary;
- preserve the immutable v0.3.0 tag and publish the fix as v0.3.1.
