# v0.2.0 second-round generalization study

## Abstract

This confirmatory replication uses a different benchmark family and agent implementation from the v0.1.0 SWE-agent pilot. The source was fixed before reading its result: Multi-SWE-bench Verified Go, `20250329_MagentLess_Claude-3.7-Sonnet`, at immutable repository commit `6a7d5566f62fa76f4192302cf763051b98e4facc`. Of 341 submitted/completed patches, 25 were resolved and 316 unresolved. Under the preregistered generated-output baseline, the oracle-unsupported completion-label rate was 92.67% (95% Wilson 89.40%–94.99%). The preregistered H1 is supported for this single source. This is not a prevalence estimate and does not establish semantic incorrectness.

## Preregistered source and minimums

- Benchmark family: Multi-SWE-bench Verified
- Language: Go
- Agent: MagentLess with Claude 3.7 Sonnet
- Total tasks: 428
- Required completed claims: at least 50
- Allowed incomplete/unstopped share: at most 10%
- Required unsupported rate: above 20%
- Required 95% Wilson lower bound: above 20%

The Python Agentless and Java MagentLess files inspected during schema feasibility were excluded from the confirmatory sample.

All required count identities passed: completed equals submitted, and resolved plus unresolved equals completed.

## Sensitivity analysis

If all 87 empty/error patches are removed from both the completed denominator and unresolved numerator, the remaining descriptive unsupported rate is 229/254 = **90.16%**. This remains above the preregistered threshold, but the subtraction assumes those empty/error patches are a subset of unresolved cases as indicated by the aggregate schema.

To reduce the observed rate to at most 20%, 248 of 316 unsupported claims—**78.48%**—would need to be reclassified as acceptable despite the supplied executable result. There were no unstopped instances, so inclusion/exclusion of incomplete execution does not change the result.

Policy B, based on natural-language agent self-report, is `UNTESTABLE HERE` because the fixed result file does not contain a ground-truthed self-report field.

## Adapter validity

The generic four-state vocabulary maps consistently:

- resolved completed claim → `SUPPORTED`
- unresolved completed claim → `FAILED`
- non-reconcilable or unstopped evidence → `UNVERIFIABLE`
- no submitted patch → `NO_CLAIM`

This demonstrates representational compatibility across two benchmark families. It does not prove that one contract can capture every real repository's notion of completion.

## Threats and negative results

- The source is one purposively selected Go submission, not a random population sample.
- Multi-SWE-bench is closely related to SWE-bench, so this is benchmark-family extension rather than full real-world generalization.
- Empty/error patches explain some failures but not most of the rate under the defined sensitivity calculation.
- Executable resolution is scoped evidence, not final semantic correctness.
- No natural-language completion claims, reviewer-time measurements, or adoption data are available.
